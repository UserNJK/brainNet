What it takes to run a "bare consciousness"

The project does not claim to detect consciousness — the awareness battery measures correlates (ignition, integration, criticality). What the scaling analysis in docs/HARDWARE.md can say, rigorously, is what hardware runs the network at a given scale and speed — and where the real bottleneck is.

The headline: the code is the wall, not the card

The RTX 3070 is only ~2.5× faster than CPU at N=3,000 — because the per-step Python loop (many small tensor ops, .item() syncs, the analyzers) dominates and leaves the GPU ~99% idle. A fused CUDA / GeNN-style kernel would be ~100–1000× faster on the same hardware. The knowledge graph independently flagged the O(N²) GrowthCone and ThoughtDetector as the next things to sparsify.

Two pluggability axes, one uniform API

Both backends are swapped by what you pass the constructor — nothing downstream changes, because each alternative exposes the same interface as the default. Both swaps are pinned by a regression test.

The 12 subsystems the graph partitioned on its own

Why BrainNet bridges six communities: reading BrainNet.__init__ (core.py:1271–1289) confirmed what high betweenness predicted. It assembles Neurochemistry, the core neurons & analyzers, and one polymorphic synapse backend; meanwhile build_cortex(), the awareness battery, and the reward API all bridge inward. The dense/sparse pair and the state/chemistry pair show up as bridged-but-distinct clusters — which is precisely why test_sparse_matches_dense() is the most load-bearing regression test in the suite.
